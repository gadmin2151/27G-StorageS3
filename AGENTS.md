# Работа над 27G-StorageS3

Перед изменениями прочитайте [контекст проекта](docs/PROJECT_MEMORY.md), [README](README.md) и при работе с S3 — [матрицу совместимости](docs/S3-COMPATIBILITY.md). Эти файлы сохраняют требования, принятые решения и проверенное состояние для продолжения с другого устройства; отдельная память прежнего чата не нужна.

- Название продукта — **27G-StorageS3** (сохранить это написание); название GitHub-репозитория — **27G-StorageS3**. Общение и пользовательская документация преимущественно на русском.
- Главный приоритет: удобное управление через веб-панель, встроенная Wiki, простой Docker-запуск и подключение узлов. Новые возможности управления сопровождать интерфейсом и понятной документацией.
- Стек: Node.js 22.13+, встроенный `node:sqlite`, ES modules, браузерный JavaScript/CSS без сборки. Внешних npm-зависимостей сейчас нет; не добавлять их без конкретной необходимости.
- Сохранять инварианты записи, чтения и смены топологии из `docs/PROJECT_MEMORY.md`. Это объектные аналоги RAID, а не блочный RAID. HA каталога включается отдельно по `docs/HA.md`: master/slave, арбитр etcd, fencing; зеркала blobs сами по себе отказ координатора не решают.
- Не выдавать ограниченный S3 API за полную совместимость. Неподдерживаемые операции должны явно отклоняться; при изменении контракта обновлять матрицу совместимости и Wiki в `web/app.js`.
- Проверять изменения по их риску: `node --test tests/*.test.mjs` для логики; браузер для интерфейса; `docker compose config --quiet` для Compose. Прямой запуск: `node src/server.mjs`. Не считать проверку конфигурации доказательством запуска контейнеров.
- Сохранять защиту аутентификации, SigV4, CSRF, Origin, безопасной выдачи объектов и доверенных proxy. Не помещать реальные секреты, `.env`, SQLite, volumes, содержимое хранилища, сессии или журналы в Git. Для скриншотов использовать демонстрационные данные без ключей и токенов.
- Не удалять рабочие volumes и данные ради проверки. Изменения схемы каталога и протокола узлов требуют продуманного обновления и восстановления; действующий одиночный координатор нельзя просто запускать в нескольких экземплярах.
- После существенного этапа обновлять `docs/PROJECT_MEMORY.md`: дата, что изменилось, команды и результаты проверки, оставшиеся ограничения и следующий шаг. Записывать факты и решения, не секреты и не внутренние рассуждения. Не подменять прежние результаты предположениями о новом окружении.
