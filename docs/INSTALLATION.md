# Установка и обновление 27G-StorageS3

Установщик разворачивает один координатор с веб-панелью и локальным хранилищем в Docker. При повторном запуске он распознаёт установленный им экземпляр и предлагает совместимое обновление образа с сохранением подключённого volume. После запуска бакеты, пользователей, ключи и узлы можно настраивать через браузер. Для отказоустойчивого master/slave используйте отдельную [инструкцию HA](HA.md); для подключения дисков другого сервера — команду **«Кластер → Подключить сервер»** и [инструкцию дискового агента](DISKS.md).

## Одна команда

В терминале Linux:

```sh
curl -fsSL https://github.com/gadmin2151/27G-StorageS3/releases/latest/download/install.sh | bash
```

Нужны `bash`, `curl`, `python3`, `sha256sum`, Docker Engine с плагином Compose 2.20+ и доступ root либо `sudo`. Поддерживаются Linux `amd64` и `arm64`. Node.js на сервер устанавливать не нужно: он уже входит в контейнер.

Мастер читает ответы из `/dev/tty`, поэтому вопросы работают при запуске через pipe. Если в системе есть `whiptail`, используются диалоговые окна; иначе — текстовые вопросы. Мастер предлагает:

1. Каталог установки — по умолчанию `/opt/27g-storage-s3`. Родительский каталог должен уже существовать; путь задаётся без пробелов и символических ссылок.
2. Порт — по умолчанию `9000`.
3. IPv4-адрес для публикации порта — по умолчанию `127.0.0.1`, только этот сервер. Можно выбрать `0.0.0.0` либо конкретный адрес сервера.
4. Необязательный публичный адрес, например `https://s3.example.com`, если DNS и HTTPS-прокси уже настроены.
5. Подтверждение параметров перед установкой.

Поле публичного адреса определяет адрес ссылок и проверку Origin. Оно **не настраивает DNS и не выпускает TLS-сертификат**. Внешний порт в этом адресе — порт HTTPS-прокси, если он отличается от внутреннего `9000`. При первом запуске через SSH можно оставить поле пустым и настроить его позже в панели.

Если Docker отсутствует, интерактивный мастер может предложить установку из официального apt-репозитория на Debian/Ubuntu. Это отдельное подтверждение. На других дистрибутивах сначала установите Docker Engine и Compose самостоятельно. Скрипт не заменяет уже существующую или конфликтующую конфигурацию Docker.

## Что создаёт установщик

В выбранном каталоге:

| Файл или каталог | Назначение |
|---|---|
| `compose.yaml` | Сервис `app`, порт, публичный адрес и параметры контейнера |
| `INSTALLATION.json` | Сведения об установленной версии и способе установки |
| `source/` | Проверенные исходники первой установки |
| `releases/vX.Y.Z/` | Исходники последующих успешно установленных версий |

Данные хранятся в отдельном именованном Docker volume. Имя Compose-проекта имеет вид `27g-storage-s3-<12 символов SHA-256 каталога>`, volume — `<имя проекта>_data`. Это позволяет устанавливать независимые экземпляры в разные каталоги при разных портах. Не меняйте имя проекта или volume при обновлении: иначе можно получить новый пустой экземпляр вместо прежнего хранилища.

Установщик разрешает `latest` в конкретную версию, скачивает релизный архив и проверяет его SHA-256 по `SHA256SUMS`. Готовый GHCR-образ сохраняется в Compose с digest; обычный перезапуск не переключает его на новую версию. Если образ недоступен, мастер предлагает локальную сборку из проверенного архива. Для явного выбора сборки есть `--build`.

Команда через pipe доверяет полученному по HTTPS установщику. Контрольная сумма архива проверяется уже внутри него; это не независимая подпись самого скрипта. Если нужно предварительно изучить код, скачайте файл и запустите после просмотра:

```sh
curl -fsSL -o install.sh https://github.com/gadmin2151/27G-StorageS3/releases/latest/download/install.sh
less install.sh
bash install.sh
```

## Первый вход

При стандартных настройках откройте **http://127.0.0.1:9000/console/**. Для сервера по SSH создайте туннель на своём компьютере:

```sh
ssh -L 9000:127.0.0.1:9000 user@server
```

Начальная учётная запись — `admin`, пароль — `admin!123`. В Docker форма также требует случайный **Initial setup token**. Установщик не печатает его автоматически; получить его можно на сервере:

```sh
sudo docker compose -f /opt/27g-storage-s3/compose.yaml exec -T app cat /data/setup.token
```

Если выбран другой каталог, замените путь после `-f`. Не отправляйте токен в общий чат или Git. В настройках панели задайте собственный пароль от 12 символов; после этого токен для входа не нужен. Уже изменённые учётные данные сохраняются при перезапуске.

## Параметры командной строки

Параметры передаются после `bash -s --`:

```sh
curl -fsSL https://github.com/gadmin2151/27G-StorageS3/releases/latest/download/install.sh | bash -s -- --version v0.3.1 --directory /opt/27g-storage-s3 --port 9000
```

| Параметр | Действие |
|---|---|
| `--yes` | Установка без вопросов с указанными параметрами и безопасными значениями по умолчанию |
| `--update` | Явно разрешить обновление найденной установки; при автоматическом запуске требуется вместе с `--yes` |
| `--version v0.3.1` | Выбрать конкретный релиз; по умолчанию `latest` |
| `--directory /opt/27g-storage-s3` | Каталог конфигурации и исходников |
| `--port 9000` | Опубликованный порт хоста |
| `--bind 127.0.0.1` | Только локальный доступ; также допустимы `0.0.0.0` и конкретный IPv4 |
| `--public-origin https://s3.example.com` | Уже работающий внешний origin без пути, query и fragment |
| `--build` | Собрать образ на сервере из проверенных исходников выбранного релиза |
| `--install-docker` | Явно разрешить установку отсутствующего Docker на поддерживаемом Debian/Ubuntu |
| `--help` | Показать встроенную справку |

Для автоматизации заранее обеспечьте root или доступ `sudo` без интерактивного пароля; `--yes` не отменяет политику `sudo`. Пример с установленным Docker:

```sh
curl -fsSL https://github.com/gadmin2151/27G-StorageS3/releases/download/v0.3.1/install.sh | bash -s -- --yes --version v0.3.1 --directory /opt/27g-storage-s3 --bind 127.0.0.1 --port 9000
```

С `--yes` скрипт не должен угадывать разрешение на установку Docker или локальную сборку после ошибки загрузки образа. Для этих действий передайте соответственно `--install-docker` или `--build`.

## Управление и повторный запуск

Используйте путь к конфигурации своей установки:

```sh
sudo docker compose -f /opt/27g-storage-s3/compose.yaml ps
sudo docker compose -f /opt/27g-storage-s3/compose.yaml logs --tail 100 app
sudo docker compose -f /opt/27g-storage-s3/compose.yaml stop app
sudo docker compose -f /opt/27g-storage-s3/compose.yaml start app
```

Журналы первой установки могут содержать setup token; не публикуйте их целиком. Контейнер автоматически запускается после перезапуска Docker благодаря `restart: unless-stopped`, если ранее не был остановлен вручную.

Повторный запуск той же команды распознаёт установку по `INSTALLATION.json` в выбранном каталоге и предлагает обновление. Существующие настройки и имя volume сохраняются. Произвольный каталог без записи установщика не используется. Не удаляйте каталог и volume ради повторной попытки: при ошибке сначала прочитайте сообщение и проверьте `docker compose ps` и журналы.

Одновременные запуски для одного каталога блокируются: рядом с ним на время операции создаётся `<каталог установки>.installer-lock`. При обычном завершении блокировка снимается автоматически.

GitHub Actions выпускает новые образы и релизные файлы, но не подключается к вашему серверу и не перезапускает его. Обновление начинает администратор повторным запуском установщика. Скрипт не копирует объекты или базы данных для обновления.

## Обновление существующего сервера

Используйте ту же команду, что при установке, и укажите прежний каталог, если он отличается от стандартного:

```sh
curl -fsSL https://github.com/gadmin2151/27G-StorageS3/releases/latest/download/install.sh | bash
```

Мастер показывает установленную и предлагаемую версии и спрашивает подтверждение. В автоматизации разрешение на обновление задаётся явно:

```sh
curl -fsSL https://github.com/gadmin2151/27G-StorageS3/releases/latest/download/install.sh | bash -s -- --yes --update --directory /opt/27g-storage-s3
```

Можно выбрать конкретную более новую версию через `--version vX.Y.Z`. При совпадении версий изменений нет; переход на более старую версию отклоняется. `--update` не создаёт новую установку, если по выбранному пути нет действующего экземпляра.

Скрипт сохраняет порт, адрес публикации, публичный origin, имя проекта, пользователей, ключи, бакеты, объекты, версии и настройки из действующей установки. При обновлении не передавайте `--port`, `--bind` и `--public-origin`: скрипт сохраняет прежние значения и отклоняет эти параметры. Если `compose.yaml` вручную меняли после установки, автоматическое обновление останавливается: чужие изменения не перезаписываются.

Порядок обновления:

1. Пока старый сервер работает, скачиваются релиз и образ, проверяется SHA-256 и совместимость формата данных.
2. Новая версия проходит проверку запуска с пустым временным `/data` в RAM (`tmpfs`) без опубликованных портов. Рабочие данные на этом шаге не подключаются.
3. Сохраняются прежняя конфигурация и идентификатор старого образа. Координатор штатно останавливается; затем формат существующих данных дополнительно проверяется в режиме только чтения.
4. Запускается новый образ с **тем же volume данных** и на прежнем порту, затем проверяется его готовность.

Объекты, SQLite и секреты не копируются. Обновление не создаёт вторую копию хранилища и не обходит все объекты. Нужен запас места для загрузки образа и небольшой тестовой установки. Краткий перерыв в доступности начинается при остановке старого контейнера.

Автоматически разрешены только обновления с совместимым форматом данных, при которых прежний образ может снова открыть тот же volume. Несовместимый контракт релиза отклоняется до остановки работающего сервера; дополнительная проверка существующих данных выполняется после его штатной остановки. Обновления с необратимой миграцией формата требуют отдельной процедуры и этим установщиком не выполняются.

Прежние `compose.yaml`, `INSTALLATION.json` и идентификатор образа `old-image-id` сохраняются в `backups/<UTC>-<старая версия>-<PID>/` внутри каталога установки. Если запуск совместимого нового образа не удался, установщик возвращает прежний образ и конфигурацию с тем же volume. Сохранение конфигурации и образа предназначено для отката программы; **резервной копии пользовательских данных скрипт не создаёт**. Для защиты от отказа диска, ошибочного удаления и других потерь используйте отдельный [backup хранилища](OPERATIONS.md#резервное-копирование-и-восстановление).

Файл `update-state.json` отмечает незавершённую операцию. Если установка прервалась и этот файл остался, новый запуск не начинает второе обновление поверх первого. Порядок восстановления приведён ниже; не удаляйте файл состояния или volumes без проверки работающего экземпляра.

Установки из `git clone` и вручную созданные Compose-конфигурации этот мастер не подхватывает автоматически. Для них применяется собственный порядок обновления. Для HA действуют отдельные требования из [HA.md](HA.md).

### Если питание или процесс прервали обновление

Сначала убедитесь, что предыдущий установщик больше не работает. Прочитайте состояние операции и статус контейнера:

```sh
sudo cat /opt/27g-storage-s3/update-state.json
sudo docker compose -f /opt/27g-storage-s3/compose.yaml ps -a
```

В JSON указаны `phase`, `oldImageId`, `volume` и `configurationBackup`. Каталог `configurationBackup` содержит прежние `compose.yaml` и `INSTALLATION.json`. Для возврата к прежнему совместимому образу:

1. Проверьте, что образ `oldImageId` и volume с именем `volume` существуют (`sudo docker image inspect …` и `sudo docker volume inspect …`). Если они отсутствуют, не создавайте вместо них пустые: сначала выясните причину.
2. Остановите сервис командой `sudo docker compose -f /opt/27g-storage-s3/compose.yaml stop app`.
3. Скопируйте **только** `compose.yaml` и `INSTALLATION.json` из указанного `configurationBackup` в каталог установки, сохранив права доступа. Volume и его содержимое не заменяются.
4. Выполните `sudo docker compose -f /opt/27g-storage-s3/compose.yaml up -d --wait`. Проверьте вход в панель, ожидаемые бакеты и чтение файлов.
5. После успешной проверки переместите `update-state.json` в каталог `configurationBackup` для истории. Сохранённые конфигурации и старый образ можно оставить до завершения проверки новой версии.

После потери питания или `SIGKILL` может остаться пустой каталог `/opt/27g-storage-s3.installer-lock`. Когда работающий установщик исключён и восстановление завершено, удалите **только эту пустую блокировку** командой `sudo rmdir /opt/27g-storage-s3.installer-lock`. Если сбой произошёл до остановки сервера и `update-state.json` ещё не создан, сначала проверьте, что прежний экземпляр работает, затем снимите оставшуюся блокировку. Для другого каталога установки путь блокировки меняется соответственно.

Эта процедура относится к совместимым обновлениям данного установщика. `down -v`, удаление volumes и запуск произвольной старой версии поверх данных для восстановления не нужны.

## Ошибки загрузки и ограничения

- **GitHub возвращает 404:** проверьте наличие нужной версии на [странице Releases](https://github.com/gadmin2151/27G-StorageS3/releases). Адрес `latest` появляется после успешной публикации первого стабильного релиза.
- **GHCR отвечает denied/unauthorized:** владелец должен открыть доступ к пакету. В качестве альтернативы выберите сборку на сервере (`--build`); отдельный GitHub-токен для общедоступного исходного архива не нужен. [Настройки публикации образов](CI-CD.md).
- **Нет интерактивного терминала:** запустите команду из обычного SSH-терминала либо задайте `--yes` и все нужные параметры.
- **Порт занят:** выберите другой порт или разберитесь с существующим сервисом; скрипт не должен останавливать чужие контейнеры.
- **Ссылка открывается только локально:** `127.0.0.1` относится к компьютеру получателя. Для доступа с других устройств настройте сеть и доступный им адрес; для Интернета — HTTPS.

Установка не форматирует диски, не настраивает HA и не переносит существующие данные. Присоединение агентов и управление дисками выполняется отдельно через панель. Ограничения S3 и сохранности данных остаются теми же, что в [README](../README.md) и [матрице совместимости](S3-COMPATIBILITY.md).
